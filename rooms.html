联机房间操作

服务器通过 Web 管理端或 REST API 创建、加入、离开房间，并生成邀请链接供玩家加入。

三种邀请形式

形式示例说明
短码ABC123由外部短码服务托管，更方便传播；服务不可用时建房降级为仅离线串
完整邀请链接https://next.astral.fan/j?c=ABC123从 URL 的 c 参数提取令牌
AG1. 离线串AG1.xxxxx…完全自包含、不依赖短码服务

短码输入时会先做规范化：去空白 / 连字符 / 下划线并转大写，I/L → 1、O → 0（对齐 Crockford Base32 去歧义规则）。

房间生命周期

创建房间

  1. 读取已启用的中继服务器（未启用任何服务器则报错，房间必须至少有一个 peer）；
  2. 随机生成网络名 network_name（ag_ + 10 位）与网络密钥 network_secret（16 位、剔除易混淆字符）；
  3. 编码 AG1. 离线串，并尝试向短码服务注册短码（失败不阻断）；
  4. 用服务端资料 + 房间网络身份组装 EasyTier TOML 并启动实例；
  5. 写入当前房间会话并生成分享链接。

加入 / 离开房间

加入流程与建房共用同一套核心逻辑：解析邀请（自动识别三种格式）→ 构建房间 → 启动节点 → 写入当前房间。离开则停止实例、清空当前房间并广播 room.left（不发邮件）。

REST 接口

接口方法说明
/api/room/createPOST请求体：game_id、game_name、display_name（可选）
/api/room/joinPOST请求体：input（短码 / 链接 / AG1. 离线串）
/api/room/leavePOST离开房间
/api/room/currentGET当前房间与分享链接（无房间时 room 为 null）

game_id 取自内置游戏列表（见中继服务器与游戏目录），custom 表示自定义网络。

房间数据模型

字段说明
is_host本机是否为房主（创建为 true，加入为 false）
game_id / game_name游戏标识 / 名称
network_name / network_secretEasyTier 网络名 / 密钥（同房间成员必须一致）
display_name房间展示名（缺省时取游戏名）
short_code短码（服务不可用时为 null）
offline_inviteAG1. 离线邀请串（始终可用）
peers本房间使用的中继 / 对等节点端点列表
